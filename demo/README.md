# Rilvento — локальное исследовательское демо

**ДЕМО КОНЦЕПЦИИ. Синтетические данные. Интеграции имитированы.**

Требуется Python 3.12. Проверено на Windows, Python 3.12; Linux/macOS не проверялись. Первый запуск загружает закреплённые Python-зависимости из публичного реестра PyPI; далее интерфейс, граф и /docs работают локально без CDN.

Из этой папки одна команда:

```powershell
python run.py
```

Из корня выданных материалов: `python demo/run.py`. Скрипт создаёт `.venv`, устанавливает зависимости при их отсутствии и запускает сервер только на 127.0.0.1:8765. Открыть [демо](http://127.0.0.1:8765) и [документацию API](http://127.0.0.1:8765/docs). Остановка — Ctrl+C в окне запуска. Порт должен быть свободен.

По умолчанию SQLite находится в `data/demo.sqlite`, создаётся автоматически. Не удалять этот файл ради «исправления» журнала. Для чистой независимой репетиции можно указать **новый** путь в переменной `DEMO_DB`, затем выполнить ту же команду. Сохранённая прежняя база останется нетронутой.

## Сценарий

1. Роль «Аналитик» → открыть DEMO-017 → «Граф и факты». Два перехода вычисляет networkx.
2. Открыть источник TX-01. «Досье происхождения» разделяет граф и экономические документы.
3. Собрать обоснование. Нажать ссылки. Это TemplateWriter, не генеративная модель.
4. Подготовить черновик запроса документов. Отправки нет. Добавить синтетическую выписку, создать новую версию.
5. В «Согласовании» аналитик не может утвердить. Переключить на утверждающего; согласовать досье с ограничениями.
6. Администратор → «Имитировать недоступность». Утверждающий видит блокировки и может эскалировать.
7. «Журнал» → проверить цепочку. При необходимости аудитору доступен внутренний JSON-экспорт.

Подробный пяти минутный сценарий — в `../presentation/slides.md`.

## API и проверки

В `/docs`: нажать Authorize, ввести `local-demo` для заголовка `X-Demo-Action`, выполнить `/api/login` с выбранной демо-ролью. Браузер сохраняет HttpOnly-сессию; последующие запросы проверяют серверные права. Маркер — защита демонстрационных запросов от простого межсайтового вызова, **не секрет и не полноценная аутентификация**.

После первого запуска:

```powershell
.venv/Scripts/python.exe -m pytest tests -q
```

На Linux/macOS путь к интерпретатору: `.venv/bin/python`. Эти платформы не испытывались. Тесты создают изолированные базы во временной папке и не трогают демонстрационную историю. В отчёте рядом с материалами — фактический результат, а не обещание всех свойств.

Стек: FastAPI, Pydantic, SQLAlchemy, SQLite, networkx, Cytoscape.js. Точные версии — requirements.txt; полное зафиксированное окружение — requirements-lock.txt. Внешний LLM-адаптер только спроектирован через интерфейс Writer: реализован один TemplateWriter. Alembic, PostgreSQL и контейнерный запуск отложены и не проверены.

## Границы

- Любой может выбрать любую роль на локальном стенде. Личности и разделение независимых сотрудников не установлены. Серверные права действий при этом проверяются.
- Утверждается версия досье с ограничениями; операция не проводится и доход законным не признаётся.
- Валидация ссылок не удостоверяет источник и не проверяет подлинность документов.
- Существующие версии, решения и события защищены от обычного UPDATE/DELETE SQL-триггерами. Владелец БД может снять триггеры и переписать всю цепочку; внешней доверенной контрольной точки нет.
- Только один учебный случай и демонстрационный процесс. Нет загрузки реальных файлов, очередей фоновых задач, аппаратного хранения ключей, резервного копирования, регуляторной отчётности и реальных провайдеров.
- Нельзя переносить стенд в общую сеть или использовать для реальных решений без отдельного проектирования защиты и юридической оценки.

Локальные сторонние библиотеки: `static/vendor/manifest.json` содержит URLs и SHA-256; лицензии Cytoscape (MIT) и Swagger UI (Apache 2.0) сохранены рядом. Данные полностью синтетические; служебные адреса содержат DEMO и не предназначены для блокчейна.
